# YxWoof v2：核心技术思想

本目录摘录 v2 的核心源码，用于展示简历中五项优化的实现思路。原仓库 v1 的代码、页面、配置、文档与资源保持不变。

这是**源码阅读版**：保留核心模块在原工程中的依赖关系，不提供独立运行环境、部署脚手架、完整页面或测试数据。

## 技术要点与源码

| 优化要点 | 使用的技术与实现效果 | 入口 |
| --- | --- | --- |
| **时态规则匹配** | 不可变知识版本、业务有效期、订单权益与依据快照；按下单/支付/签收/申请时间取证，避免用今天的规则回答历史订单 | [temporal.py](core/temporal.py) |
| **多意图与上下文治理** | LangGraph 结构化理解、上下文改写、依赖编排和 PostgreSQL 持久状态；多订单诉求分别处理，缺少信息时澄清，旧兜底由用户明确继续 | [agent.py](core/agent.py)、[domain.py](core/domain.py) |
| **场景化多路召回** | 原始向量、上下文改写、子问题、标题字段与 BM25 召回，共同执行授权和时态过滤；候选配额、加权 RRF 与分项重排控制覆盖度和查询漂移 | [retrieval.py](core/retrieval.py) |
| **异常退出与受控恢复** | 异步数据库、共享截止时间、依赖熔断、模型串行与费用预占；控制版本抑制迟到回复，原动作核对和幂等补记避免恢复时重复办理 | [runtime.py](core/runtime.py)、[db.py](core/db.py)、[recovery.py](core/recovery.py) |
| **反馈驱动的持续改进** | 回复级评价、周期聚类、人工审核、培训材料失效管理和版本化回归集；形成审核—评测—手动发布机制，培训 QA 与在线 RAG 保持隔离 | [learning.py](core/learning.py)、[models.py](core/models.py) |

## 建议阅读顺序

1. **规则与证据**：`temporal.choose_versions`、`merge_rules`、`policy_snapshot`。活动生效不等于订单参加活动；只有日期时保留日期精度，无法唯一确定规则就要求补充。
2. **理解与执行**：`agent.py` 中的结构化计划、对话改写、LangGraph 节点，以及 `domain.py` 中的轮次与子任务状态。单轮最多承接 4 项，历史未答事项不自动进入当前回答范围。
3. **检索与生成**：`retrieval.retrieve` 统一过滤后选择路线、配额合并与重排；`agent.validate_answer` 检查必要结论和引用。原始候选 20、扩展各 10、合并最多 40，每事项最多保留 5 条依据。
4. **异常与竞态**：`runtime.Budget`、`CircuitBreaker`、`db.BoundedSession`、`recovery.scan`。服务端整轮预算 30 秒；模型锁等待最多 2 秒；网络取消之外，持久版本校验负责阻止过时回复。
5. **反馈与沉淀**：`domain.save_feedback`、`learning.analyze`、培训审核与回归集冻结逻辑。用户低分不直接等于答案错误；标准答案由审核人员确认，材料在依据变化或到期时停止作为现行指引使用。

## 设计边界

- **模型与业务分工**：模型负责理解和有据应答，权限、规则适用、预览确认和幂等提交由确定性逻辑处理。申请受理不代表退款到账。
- **跨轮次一致性**：PostgreSQL 保存权威业务状态，LangGraph 编排单轮节点；恢复服务不重放历史问题或写操作，未知结果仅核对原动作。
- **检索以评测决定启用**：扩展路线默认关闭，须在新冻结集证明增益后启用；引用存在校验不能替代语义正确性评测。
- **培训与 AI 改进分离**：常见 QA 仅供人工培训，不进入在线检索、直接回复或模型训练；回归案例独立审核，发布由维护者手动执行。
